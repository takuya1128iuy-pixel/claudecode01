# アパレル販売サポートアプリ 要件整理（v1: 2026 FW）

作成日: 2026-08-29 / ステータス: ドラフト（ヒアリング前）

---

## 0. このドキュメントの位置づけ

「アパレル販売員が、スマホの隙間時間にカラー・素材・トレンドを確認できるアプリ」を作るための要件整理。
実装前に、**何を作るか / 何を作らないか / データをどこから持ってくるか** を決めることを目的とする。

未確定の部分は「§11 確認したいこと」に集約した。ここが埋まれば v1 の実装に入れる。

---

## 1. 背景と課題

アパレル販売の現場では、以下が日常的に発生する。

| 場面 | 現状の困りごと |
| --- | --- |
| 接客中 | 「この色に何を合わせれば？」と聞かれ、その場で提案の引き出しが必要 |
| 接客中 | 「この素材って洗える？チクチクしない？」に即答したい |
| シーズン初め | シーズンテーマ・推し色・推し素材を覚えきれない／忘れる |
| 出勤前・休憩中 | 学ぶ時間はあるが、まとまった時間はない（5分未満の細切れ） |
| 情報源 | 社内MD資料・展示会メモ・雑誌・SNSに散らばっていて、店頭では開けない |

→ **紙資料やPDFは店頭で開けない。スマホで1〜3タップで答えに届くことが最重要。**

---

## 2. 目的（このアプリで達成したいこと）

1. **隙間時間（1〜5分）でシーズン知識をインプットできる**
2. **接客中に3タップ以内で「合わせる色 / 素材の説明 / 提案トーク」に到達できる**
3. **自分の接客で効いた組み合わせを記録し、翌シーズンの資産にする**

### 成功指標（v1の判断基準）

- 「今日の1枚」を週5日以上開いている
- 接客中に実際に開いた回数 / 週（自己申告でよい）
- シーズン終了時に「売れた組み合わせメモ」が20件以上たまっている

---

## 3. ユーザーと利用シーン

### 主ユーザー: アパレル販売員（本人）

- 端末: iPhone（Safari / ホーム画面追加）
- 姿勢: **片手・縦持ち・立ったまま**
- 使う時間帯:
  - 出勤前の電車（3〜10分）… インプット
  - バックヤードでの休憩（1〜5分）… 復習・確認
  - **接客の直前・最中（10〜30秒）… 逆引き検索**
  - 退勤後（3分）… 今日売れた組み合わせをメモ

### 副次ユーザー（v2以降）: 同じ店舗のスタッフ

- 共有・閲覧のみ。v1では対象外（データ共有の仕組みが必要になるため）。

### 明確に対象外

- お客様に直接見せるカタログアプリ（画像の権利処理が別問題になる）
- 在庫管理・POS連携・売上管理（会社システムの領域）

---

## 4. スコープ（v1 = 2026年秋冬）

### v1でやること

- 2026 FW のカラー / 素材 / シーズンテーマの**閲覧**
- 配色ルールと「この色に合う色」の**逆引き**
- 素材の特徴・お手入れ・接客トークの**参照**
- 自分用メモ（売れた組み合わせ / よく聞かれる質問）の**記録**
- オフラインで動くこと

### v1でやらないこと（意図的に外す）

| 外すもの | 理由 |
| --- | --- |
| ログイン / アカウント | 個人利用のため不要。端末内保存で足りる |
| サーバー・DB | 運用コストとメンテが発生する。まず価値検証 |
| 複数端末同期 | 上に同じ。必要になったら v2 |
| 商品在庫・品番連携 | 会社システムの領域。個人アプリの範囲を超える |
| お客様の個人情報の記録 | **法的・倫理的リスク。恒久的に対象外とする** |
| 画像の自動収集 / スクレイピング | 著作権侵害リスク |
| AIによる自動コーデ生成 | v1は「正確な既知の情報を早く引ける」ことに集中 |

## 5. 機能要件

優先度: **Must**（v1必須） / **Should**（v1に入れたい） / **Could**（v2以降）

### F1. カラー（配色）— Must

| ID | 機能 | 優先度 |
| --- | --- | --- |
| F1-1 | 2026FW シーズンカラー一覧（色名・カラーチップ・読み方・出典） | Must |
| F1-2 | 色詳細: 相性の良い色 / 避けたい組み合わせ / 面積比の目安 | Must |
| F1-3 | **逆引き**: 「黒に合うトレンド色は？」から検索 | Must |
| F1-4 | ベーシック色（黒・ネイビー・グレー・ベージュ・白・デニム）× トレンド色の相性マトリクス | Must |
| F1-5 | 配色パターンの解説（後述の配色ロジック） | Should |
| F1-6 | パーソナルカラー4分類（イエベ春/秋・ブルベ夏/冬）との相性表示 | Should |
| F1-7 | 2色を選ぶと配色イメージをその場でプレビュー（面積比つき） | Could |

#### 収録する配色ロジック（シーズンに依存しない普遍ルール）

- **面積比 70 : 25 : 5**（ベース / アソート / アクセント）
- **トーンオントーン**（同色相・明度差） / **トーンイントーン**（同トーン・色相差）
- **セパレーション**（白・黒・グレーで色を仕切る）
- **明度の縦配置**（明るい色を上に置くと軽く見える）
- **差し色は小物から**（バッグ・靴・マフラーで冒険する提案）
- **秋冬のトーン**（低明度・低彩度が基本、そこに1点の高彩度）

## 6. 非機能要件

### 6.1 パフォーマンス / 操作性（最重要）

- **3タップ以内**で目的の情報に到達する
- 初回表示 **1秒以内**（店頭で待てるのは体感1〜2秒まで）
- **片手・親指操作**前提 → 主要ナビは画面下部に固定
- 1画面 = 1テーマ。スクロールで情報を積まない
- 文字サイズは店頭の照明・距離を考慮して大きめ（本文16px以上）

### 6.2 オフライン動作 — Must

- 店舗バックヤード・地下フロアは電波が弱い前提
- **PWA + 静的データ同梱**で、通信なしでも全コンテンツが見られること
- メモは端末内保存（localStorage / IndexedDB）

### 6.3 店頭での使用に耐えること

- お客様から画面が見えても違和感のない、落ち着いた見た目
- 音を鳴らさない / 派手なアニメーションを使わない
- ダークモード対応（暗い店内・夜間の通勤時）

### 6.4 アクセシビリティ

- **色情報は必ずテキスト（色名 + カラーコード）を併記**（色だけで意味を伝えない）
- コントラスト比 4.5:1 以上
- タップ領域 44×44px 以上

### 6.5 プライバシー / コンプライアンス

- **お客様の個人情報は一切入力させない**（入力欄自体を作らない）
- データは端末内のみ。外部送信なし
- **画像の権利処理**: ブランド公式画像・雑誌スキャン・SNS転載は使わない。
  自分で撮影した写真、ライセンス確認済み素材、または自作のカラーチップ/イラストのみ。
- 勤務先の社内資料（MD資料・仕入情報）を**そのまま公開Webに載せない**
  → 公開URLにする場合は一般公開情報のみ。社内情報を入れるならローカル配信 or 非公開化を検討（§11-4）

### 6.6 対応環境

- iPhone Safari（最新2バージョン）を主対象、ホーム画面追加で全画面表示
- Android Chrome も動作すること（副次）
- 画面幅 360px から破綻しないこと

## 7. データ要件

### 7.1 データモデル（案）

```ts
// シーズン
type Season = {
  id: string;            // "2026fw"
  label: string;         // "2026年 秋冬"
  themes: Theme[];
};

// シーズンテーマ
type Theme = {
  id: string;
  title: string;         // テーマ名
  keywords: string[];
  description: string;
  imageIds: string[];    // ムードボード
  colorIds: string[];    // このテーマの主要色
  materialIds: string[];
};

// 色
type Color = {
  id: string;
  nameJa: string;        // 日本語色名
  nameEn: string;
  hex: string;           // "#4A5D4E"
  group: "neutral" | "warm" | "cool" | "accent" | "basic";
  tone: string;          // ダル / ディープ / ペール など
  description: string;   // どんな印象か
  goesWith: string[];    // 相性の良い色ID
  avoidWith: string[];   // 難しい組み合わせ + その理由
  ratioHint: string;     // 面積比の目安（ベース向き / 差し色向き）
  personalColor: ("spring" | "summer" | "autumn" | "winter")[];
  talk: string;          // 接客での一言
  source: string;        // 出典（必須）
};

// 素材
type Material = {
  id: string;
  nameJa: string;
  nameEn: string;
  category: "天然繊維" | "化学繊維" | "混紡" | "皮革・フェイク";
  warmth: 1|2|3|4|5;
  weight: 1|2|3|4|5;
  care: { washable: boolean; note: string; pilling: string; storage: string };
  pros: string[];
  cons: string[];
  talk: string;          // 一言説明
  faq: { q: string; a: string }[];
  source: string;
};

// コーディネート例
type Outfit = {
  id: string;
  title: string;
  imageId: string;
  scene: string;         // 通勤 / 休日 …
  silhouette: "I" | "A" | "Y" | "X";
  items: { part: string; item: string; colorId: string; materialId: string }[];
  colorRatio: { colorId: string; percent: number }[];
  point: string;
  source: string;
};

// 自分メモ（端末内のみ）
type Note = {
  id: string;
  type: "sold" | "question" | "memo";
  body: string;
  colorIds: string[];
  materialIds: string[];
  photo: string | null;  // dataURL
  createdAt: number;
};
```

### 7.2 データソース（**ここが最大の課題**）

アプリの価値は中身のデータで決まる。**すべての項目に `source`（出典）を必須とする。**

| 種別 | 想定ソース | 備考 |
| --- | --- | --- |
| トレンドカラー | JAFCA（日本流行色協会）の秋冬トレンドカラー、PANTONE のシーズンカラーレポート | 一次情報。名称・番号は正確に転記 |
| 素材知識 | 繊維メーカー・業界団体の公開情報、繊維製品の一般的知識、洗濯表示は新JIS(JIS L 0001) | 恒久的に使えるので最初に固めると良い |
| シーズンテーマ | 勤務先ブランドのMD資料 / 展示会メモ / シーズンルック | **社内資料の扱いは §6.5・§11-4 参照** |
| コーデ例 | 自分で撮影した店内コーデ、自分の私物 | 権利がクリアなのはこれ |

> **注意**: 現時点で「2026FW の具体的なトレンド」を推測で書くと、店頭で誤った情報を伝えることになる。
> v1のデータ投入時に、上記の一次情報を確認しながら埋める。

### 7.3 データ更新の運用

- コンテンツは `src/data/2026fw.json` のような **静的JSON** で持つ
- シーズンが変わったら JSON を追加し、シーズン切り替えで対応（過去シーズンも残す）
- 更新はリポジトリへの push → GitHub Actions で自動デプロイ（既存の仕組みを流用）
- **本人がアプリ内から編集できる範囲**は §11-3 で決める（開発者が更新 or 本人が編集）

## 9. 技術構成（既存リポジトリの資産を流用）

| 項目 | 選定 | 理由 |
| --- | --- | --- |
| フレームワーク | React + TypeScript + Vite | 既存リポジトリと同じ。学習コストゼロ |
| スタイル | Tailwind CSS v4 | 既存と同じ |
| グラフ | Recharts | 既存に導入済み（F6-4 の集計で使う） |
| 保存 | localStorage（メモ）/ 静的JSON（コンテンツ） | サーバー不要 |
| 配信 | GitHub Pages（GitHub Actions で自動デプロイ） | 既存の `deploy.yml` を流用 |
| PWA | manifest + apple-touch-icon + Service Worker | 既存に manifest あり。**オフライン用に Service Worker を追加**（既存アプリには未実装） |

### 既存アプリとの関係

現リポジトリには「きき酒ノート」が入っている。以下のいずれかを選ぶ必要がある（§11-5）。

- (a) 別ディレクトリ / 別リポジトリで新規に作る
- (b) 現リポジトリを本アプリに置き換える
- (c) 1つのサイトに2アプリを同居させる

### 注意点（既存アプリから学んだこと）

- iOS Safari の localStorage は、長期間未使用だとブラウザ判断で消える可能性がある
  → **メモのエクスポート（JSONダウンロード）機能を Should に入れる**

| 段階 | 内容 | 判断基準 |

## 11. 確認したいこと（ヒアリング項目）

実装前に本人に聞くべきこと。ここが決まらないと作っても外す。

### 11-1. 現場のこと

1. 扱っているのはどんなブランド／価格帯／客層か（レディース？メンズ？年代は？）
2. 実際に接客中で「答えに詰まる」のはどんな質問か（**具体例を3つ**）
3. 今は何を見て確認している？（社内資料 / メモ帳 / 検索 / 先輩に聞く）
4. 1日のうち、スマホを見られるタイミングと長さは？

### 11-2. 中身の優先度

5. カラー / 素材 / トレンド / 接客トーク のうち、**一番欲しいのはどれか**
6. 「パーソナルカラー」「骨格診断」は接客で実際に使っているか（使わないなら削る）
7. 覚えたいのは「シーズン限定の情報」か「毎年使える基礎知識」か

### 11-3. データの入れ方

8. コンテンツは誰が更新する？（開発者が更新 / 本人がアプリ内で編集したい）
9. 本人が撮った店内・コーデ写真をアプリに入れられるか（社内で撮影可か）

## 12. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| トレンド情報が不正確 | 誤った接客につながる | 全データに出典必須。推測で書かない |
| 画像の権利侵害 | 法的リスク | 自前撮影 / ライセンス確認済みのみ。公式画像の転載禁止 |
| 社内情報の公開流出 | 就業規則違反 | §11-4 で公開範囲を先に確定する |
| 作っても使われない | 労力の無駄 | Step 1（カラーのみ）で早期に検証してから広げる |
| iOS の localStorage 消失 | メモが消える | エクスポート機能を用意 |
| データ整備が続かない | シーズンごとに陳腐化 | 「毎年使える基礎知識（素材・配色ルール）」を先に厚くする |
