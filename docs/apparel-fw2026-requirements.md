# アパレル販売サポートアプリ 要件整理（v1: 2026 FW）

作成日: 2026-08-29 / ステータス: ドラフト（ヒアリング前）

---

## 0. このドキュメントの位置づけ

「アパレル販売員が、スマホの隙間時間にカラー・素材・トレンドを確認できるアプリ」を作るための要件整理。
実装前に、**何を作るか / 何を作らないか / データをどこから持ってくるか** を決めることを目的とする。

未確定の部分は「§11 確認したいこと」に集約した。ここが埋まれば v1 の実装に入れる。

---

## 1. 背景と課題

アパレル販売の現場では、以下が日常的に発生する。

| 場面 | 現状の困りごと |
| --- | --- |
| 接客中 | 「この色に何を合わせれば？」と聞かれ、その場で提案の引き出しが必要 |
| 接客中 | 「この素材って洗える？チクチクしない？」に即答したい |
| シーズン初め | シーズンテーマ・推し色・推し素材を覚えきれない／忘れる |
| 出勤前・休憩中 | 学ぶ時間はあるが、まとまった時間はない（5分未満の細切れ） |
| 情報源 | 社内MD資料・展示会メモ・雑誌・SNSに散らばっていて、店頭では開けない |

→ **紙資料やPDFは店頭で開けない。スマホで1〜3タップで答えに届くことが最重要。**

---

## 2. 目的（このアプリで達成したいこと）

1. **隙間時間（1〜5分）でシーズン知識をインプットできる**
2. **接客中に3タップ以内で「合わせる色 / 素材の説明 / 提案トーク」に到達できる**
3. **自分の接客で効いた組み合わせを記録し、翌シーズンの資産にする**

### 成功指標（v1の判断基準）

- 「今日の1枚」を週5日以上開いている
- 接客中に実際に開いた回数 / 週（自己申告でよい）
- シーズン終了時に「売れた組み合わせメモ」が20件以上たまっている

---

## 3. ユーザーと利用シーン

### 主ユーザー: アパレル販売員（本人）

- 端末: iPhone（Safari / ホーム画面追加）
- 姿勢: **片手・縦持ち・立ったまま**
- 使う時間帯:
  - 出勤前の電車（3〜10分）… インプット
  - バックヤードでの休憩（1〜5分）… 復習・確認
  - **接客の直前・最中（10〜30秒）… 逆引き検索**
  - 退勤後（3分）… 今日売れた組み合わせをメモ

### 副次ユーザー（v2以降）: 同じ店舗のスタッフ

- 共有・閲覧のみ。v1では対象外（データ共有の仕組みが必要になるため）。

### 明確に対象外

- お客様に直接見せるカタログアプリ（画像の権利処理が別問題になる）
- 在庫管理・POS連携・売上管理（会社システムの領域）

---

## 4. スコープ（v1 = 2026年秋冬）

### v1でやること

- 2026 FW のカラー / 素材 / シーズンテーマの**閲覧**
- 配色ルールと「この色に合う色」の**逆引き**
- 素材の特徴・お手入れ・接客トークの**参照**
- 自分用メモ（売れた組み合わせ / よく聞かれる質問）の**記録**
- オフラインで動くこと

### v1でやらないこと（意図的に外す）

| 外すもの | 理由 |
| --- | --- |
| ログイン / アカウント | 個人利用のため不要。端末内保存で足りる |
| サーバー・DB | 運用コストとメンテが発生する。まず価値検証 |
| 複数端末同期 | 上に同じ。必要になったら v2 |
| 商品在庫・品番連携 | 会社システムの領域。個人アプリの範囲を超える |
| お客様の個人情報の記録 | **法的・倫理的リスク。恒久的に対象外とする** |
| 記事本文のスクレイピング / 画像の自動収集 | 著作権侵害リスク。要約＋出典リンクで代替する |
| トレンド予測データの自動取得 | 提供元がすべて有料・法人契約。個人では入手経路がない（§7.3） |
| 市場実データの自動取得（L3） | **保留**。APIキー管理・規約順守・cron運用の手間に対して、v1時点では効果が読めない（§7.7） |
| AIによる自動コーデ生成 | v1は「正確な既知の情報を早く引ける」ことに集中 |

| F1-2 | 色詳細: 相性の良い色 / 避けたい組み合わせ / 面積比の目安 | Must |

#### 収録する配色ロジック（シーズンに依存しない普遍ルール）

- **面積比 70 : 25 : 5**（ベース / アソート / アクセント）
- **トーンオントーン**（同色相・明度差） / **トーンイントーン**（同トーン・色相差）
- **セパレーション**（白・黒・グレーで色を仕切る）
- **明度の縦配置**（明るい色を上に置くと軽く見える）
- **差し色は小物から**（バッグ・靴・マフラーで冒険する提案）
- **秋冬のトーン**（低明度・低彩度が基本、そこに1点の高彩度）

## 6. 非機能要件

### 6.1 パフォーマンス / 操作性（最重要）

- **3タップ以内**で目的の情報に到達する
- 初回表示 **1秒以内**（店頭で待てるのは体感1〜2秒まで）
- **片手・親指操作**前提 → 主要ナビは画面下部に固定
- 1画面 = 1テーマ。スクロールで情報を積まない
- 文字サイズは店頭の照明・距離を考慮して大きめ（本文16px以上）

### 6.2 オフライン動作 — Must

- 店舗バックヤード・地下フロアは電波が弱い前提
- **PWA + 静的データ同梱**で、通信なしでも全コンテンツが見られること
- メモは端末内保存（localStorage / IndexedDB）

### 6.3 店頭での使用に耐えること

- お客様から画面が見えても違和感のない、落ち着いた見た目
- 音を鳴らさない / 派手なアニメーションを使わない
- ダークモード対応（暗い店内・夜間の通勤時）

### 6.4 アクセシビリティ

- **色情報は必ずテキスト（色名 + カラーコード）を併記**（色だけで意味を伝えない）
- コントラスト比 4.5:1 以上
- タップ領域 44×44px 以上

### 6.5 プライバシー / コンプライアンス

- **お客様の個人情報は一切入力させない**（入力欄自体を作らない）
- データは端末内のみ。外部送信なし
- **画像の権利処理**: ブランド公式画像・雑誌スキャン・SNS転載は使わない。
  自分で撮影した写真、ライセンス確認済み素材、または自作のカラーチップ/イラストのみ。
- **社内資料は使わない（決定済み）**。コンテンツは公開情報と自前の情報のみで構成する
  → よって **GitHub Pages での公開URL配信で問題ない**。認証やローカル配信の検討は不要になった
- 外部APIのキーはリポジトリに直接書かず、GitHub Secrets に置く（§7.5）

### 6.6 対応環境

- iPhone Safari（最新2バージョン）を主対象、ホーム画面追加で全画面表示
- Android Chrome も動作すること（副次）
- 画面幅 360px から破綻しないこと

## 7. データ要件

### 7.1 データモデル（案）

```ts
// シーズン
type Season = {
  id: string;            // "2026fw"
  label: string;         // "2026年 秋冬"
  themes: Theme[];
};

// シーズンテーマ
type Theme = {
  id: string;
  title: string;         // テーマ名
  keywords: string[];
  description: string;
  imageIds: string[];    // ムードボード
  colorIds: string[];    // このテーマの主要色
  materialIds: string[];
};

// 色
type Color = {
  id: string;
  nameJa: string;        // 日本語色名（アプリ独自の呼び名）
  nameEn: string;
  hex: string;           // "#4A5D4E" ← 自前で決めた表示用の色
  group: "neutral" | "warm" | "cool" | "accent" | "basic";
  tone: string;          // ダル / ディープ / ペール など
  description: string;   // どんな印象か
  goesWith: string[];    // 相性の良い色ID
  avoidWith: string[];   // 難しい組み合わせ + その理由
  ratioHint: string;     // 面積比の目安（ベース向き / 差し色向き）
  personalColor: ("spring" | "summer" | "autumn" | "winter")[];
  talk: string;          // 接客での一言
  source: Source;        // 出典（必須）
};

// 素材
type Material = {
  id: string;
  nameJa: string;
  nameEn: string;
  category: "天然繊維" | "化学繊維" | "混紡" | "皮革・フェイク";
  warmth: 1|2|3|4|5;
  weight: 1|2|3|4|5;
  care: { washable: boolean; note: string; pilling: string; storage: string };
  pros: string[];
  cons: string[];
  talk: string;          // 一言説明
  faq: { q: string; a: string }[];
  source: Source;
};

// コーディネート例
type Outfit = {
  id: string;
  title: string;
  imageId: string;
  scene: string;         // 通勤 / 休日 …
  silhouette: "I" | "A" | "Y" | "X";
  items: { part: string; item: string; colorId: string; materialId: string }[];
  colorRatio: { colorId: string; percent: number }[];
  point: string;
  source: Source;
};

// 出典（全コンテンツで必須）
type Source = {
  kind: "own" | "public-article" | "public-report" | "market-api";
  title: string;
  url?: string;
  publisher?: string;
  checkedAt: string;     // 確認日
};

// 市場実データ（自動取得・集計結果のみを保持）
type MarketSnapshot = {
  id: string;
  fetchedAt: string;
  query: string;             // "レディース アウター 秋冬"
  colorCounts: { keyword: string; count: number }[];
  materialCounts: { keyword: string; count: number }[];
  // ※商品名・画像・価格などの生データは保存しない（§7.4）
};

// 自分メモ（端末内のみ）
type Note = {
  id: string;
  type: "sold" | "question" | "memo";
  body: string;
  colorIds: string[];
  materialIds: string[];
  photo: string | null;  // dataURL
  createdAt: number;
};
```

### 7.2 データを3層に分ける

社内資料を使わない方針が決まったため、**すべて公開情報と自前の情報だけで構成する**。
性質がまったく違うので、更新のしかたを層ごとに分ける。

| 層 | 中身 | 出どころ | 更新 | 陳腐化 |
| --- | --- | --- | --- | --- |
| **L1 不変知識** | 配色ルール、秋冬素材、洗濯表示、シルエット | 自前で執筆（一般的な知識・公開規格） | 一度作れば据え置き | しない |
| **L2 シーズン情報** | トレンドカラー、素材傾向、テーマ | 公開記事・公開レポートを**要約して手入力** | 月1回 | 半年 |
| **L3 市場実データ** | 今売られている色・素材の傾向 | 商品検索API（自動） | 週1回（自動） | 常に最新 |

**L1・L2は実装済み（§7.7）。L3はv1では保留とする。**

> **L1を最優先で作る。** 外部に一切依存せず、来年も再来年も使える。
> L2が空でもアプリは成立するが、L1が空だと成立しない。

### 7.3 外部ソースの調査結果（2026-08 時点）

| ソース | 内容 | 使えるか | 判断 |
| --- | --- | --- | --- |
| **WGSN** | トレンド予測の業界標準 | ❌ | 法人向け・見積制。「consumer use は対象外」と明記。個人利用は不可 |
| **PANTONEVIEW Colour Planner AW26/27** | 有料トレンドブック | ❌ | 有料製品。購入しても再配布は不可 |
| **PANTONE Fashion Color Trend Report (NYFW AW26/27)** | 無料の広報資料。10色＋seasonless 5色 | △ | 色名の参照は可だが §7.4 の制約が厳しい。**JAFCAで足りたため未使用** |
| **JAFCA（日本流行色協会）** | 日本市場向けトレンドカラー | ◎ | **検証済み・採用。カラーテーマと4カラーグループが無料公開されており、「ブログ等に転載される場合は、出典先を明記下さい」と明記されている。L2の一次情報とした** |
| **WWDJAPAN / madameFIGARO 等の記事** | 「2026-27年秋冬カテゴリー別リアルトレンド（アウター・素材・色柄）」など、まさに欲しい内容 | ○ | **要約＋出典リンク**なら可。全文コピー・スクレイピング再配信は不可 |
| **楽天商品検索API** | 実際に売られている商品 | ○ | 無料・商用可・アプリID登録のみ。自動化できる唯一の経路だが、v1では保留（§7.7） |
| **Yahoo!ショッピングAPI** | 同上 | ○ | 予備の選択肢。同じく保留 |

**結論: JAFCAが最良の一次情報だった。** 日本市場向けで、無料公開されていて、出典明記を条件に転載が認められている。
2026/27年秋冬レディスウェアカラー（テーマ「And And」＋4カラーグループ）をL2として採用した。

### 7.4 権利まわりの制約（設計に直接影響する）

- **PANTONE**
  - 商標ルール上、色名の前に必ず `PANTONE` を付ける必要がある
  - **PANTONE番号と他の色空間（HEX等）のクロスリファレンスは、第三者による実施が明確に禁止されている**
  - → **対応表は作らない。** アプリの表示色は**自前で決めたHEX**とし、「PANTONE 〇〇 に相当」とは書かない。
    公開レポートは「今季こういう方向性が発表された」という**文脈の引用**にとどめ、出典URLを併記する
- **記事**: 要約は自分の言葉で書く。本文の転載・画像の複製はしない。出典リンクを必ず持つ
- **商品API**: 利用規約上、取得データを丸ごと自前DBに複製する使い方は制限される
  → **個別商品データは保存しない。「色キーワードの出現数」などの集計値だけを保存する**（§7.1 `MarketSnapshot`）
- **画像**: 従来どおり自分で撮影したもの／ライセンス確認済みのものだけ

### 7.5 L3の取得方式（保留中・実装しない）

> 以下はL3を実装する場合の設計。**v1では保留**とするため、現時点では未実装（理由は §7.7）。

GitHub Pages はサーバーがないため、**ブラウザから直接APIを叩く方式は採れない**（CORSで落ちる／APIキーがJSに露出する）。

```
GitHub Actions（週1回・cron）
  └─ 商品検索APIを叩く
      └─ 色・素材キーワードを集計（生データは捨てる）
          └─ src/data/market-2026fw.json を更新してコミット
              └─ Pages へ自動デプロイ
                  └─ アプリは静的JSONを読むだけ
```

- APIキーは **GitHub Secrets** に置く。アプリ側には出さない
- アプリは常に静的JSONを読むだけなので、**オフライン要件（§6.2）と両立する**
- L2（シーズン情報）も同じ `src/data/*.json` に手入力で足していく

### 7.6 データ更新の運用

- コンテンツは `src/data/2026fw.json`（手入力）と `src/data/market-2026fw.json`（自動）に分ける
- シーズンが変わったらJSONを追加し、シーズン切り替えで対応（過去シーズンも残す）
- 手入力分の更新は push → GitHub Actions で自動デプロイ（既存の仕組みを流用）
- **全コンテンツに `source` を必須**とし、出典を書けない情報は載せない


### 7.7 実装状況（2026-08-29 時点）

| 層 | 状態 | 実体 |
| --- | --- | --- |
| **L1 不変知識** | ✅ 実装済み | `src/data/colorHarmony.ts`（配色ルール8 / ベーシック色7）<br>`src/data/materials.ts`（秋冬素材26）<br>`src/data/careLabels.ts`（洗濯表示6群 / JIS L 0001）<br>`src/data/silhouettes.ts`（I・A・Y・X） |
| **L2 シーズン情報** | ✅ 実装済み | `src/data/seasons/fw2026.ts`（JAFCA 2026/27年秋冬レディスウェアカラー：テーマ「And And」＋4カラーグループ＋29色） |
| **L3 市場実データ** | ⏸ 保留 | 未実装 |

型定義は `src/data/types.ts`、集約は `src/data/index.ts`。`npm run build`（`tsc -b`）で型検査される。

#### L1で押さえたこと

- **配色ルール**: 面積比70:25:5 / トーンオントーン / トーンイントーン / セパレーション / 明度の縦配置 / 差し色は小物から / 秋冬のトーン設計 / 色数は3色まで
- **ベーシック色**: 黒・ネイビー・グレー・ベージュ・白・ブラウン・デニム。それぞれ「合う相手」「難しい組み合わせとその理由」「接客での一言」を持つ。**逆引きの起点**になる
- **素材26種**: 暖かさ・重さ・価格帯感・長所短所・お手入れ・毛玉のできやすさ・保管方法に加えて、**接客トーク**と**実際によく聞かれる質問への回答**を各素材に持たせた
- **洗濯表示**: 桶・三角・四角・アイロン・円の5系統。「洗えますか？」に根拠を持って答えるための土台

#### L2で押さえたこと

- JAFCAのカラーテーマ「And And」と、4カラーグループの解説（JAFCA公表内容にもとづく）
- 各グループの色を、**公開カラーカード画像から実測**してHEX化（29色）
- 各色に、トーン・ベース／アソート／アクセントの役割・印象・**相性のよいベーシック色**・接客トークを付与
- グループごとに「売場でどう使うか」を追記（JAFCAの解説を販売現場向けに翻訳したもの）

#### L3を保留にした理由

1. APIキーの管理、利用規約の順守、cronの運用が必要で、**v1の検証には重い**
2. L1・L2だけでアプリとして成立する（そもそもL2が空でも成立する設計にしてある）
3. 「市場に出ている色の集計」が接客の役に立つかは、**実際に使ってもらってから判断したい**

L1・L2を使ってもらった上で「今どの色が実際に多いのか知りたい」という要望が出たら、§7.5 の方式で実装する。

#### 注意（データの扱い）

- **HEX値はJAFCA公開画像からの実測近似値**であり、JAFCAが定める色の規格値ではない。画面表示と配色の目安として使う
- **個々の日本語色名はアプリ独自の呼称**。JAFCAは個別の色名を公表していないため、「JAFCAが名付けた色名」として説明しない
- JAFCAの画像そのものは再配布していない（色の値のみ利用し、出典を明記）

## 12. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| トレンド情報が不正確 | 誤った接客につながる | 全データに出典必須。推測で書かない |
| 画像の権利侵害 | 法的リスク | 自前撮影 / ライセンス確認済みのみ。公式画像の転載禁止 |
| PANTONE等の商標・規約違反 | 権利者からの指摘 | 番号↔HEXの対応表を作らない。表示色は自前HEX。色名は出典付きの参照にとどめる（§7.4） |
| 商品APIの規約違反 | API利用停止 | 個別商品データを保存せず、集計値のみ保持（§7.4） |
| トレンド情報の入手経路が細る | L2が更新できなくなる | L1（不変知識）を厚くして、L2が空でも成立する構成にする |
| 作っても使われない | 労力の無駄 | Step 1（カラーのみ）で早期に検証してから広げる |
| iOS の localStorage 消失 | メモが消える | エクスポート機能を用意 |
| データ整備が続かない | シーズンごとに陳腐化 | 「毎年使える基礎知識（素材・配色ルール）」を先に厚くする |
