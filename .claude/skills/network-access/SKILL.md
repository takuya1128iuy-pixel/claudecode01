# 外部サイトへのアクセスが必要になったとき

このリポジトリは Claude Code のクラウド環境（隔離 VM）で動く。外向き通信は環境ごとの
**ネットワークポリシー**で制限されており、既定は **Trusted**（Anthropic / GitHub /
主要パッケージマネージャ等の許可リストのみ）。それ以外のドメインはプロキシが
403 / 407 で拒否する。

## 原則

1. **ブロックされたら回避しない。** リトライ、別経路、ミラー、プロキシ設定の変更、
   TLS 検証の無効化、`HTTPS_PROXY` の unset — すべて禁止。
   ブロックされたホスト名をそのままユーザーに報告する。
2. **黙って代替に切り替えない。** 「取れなかったので記憶から書きました」は最悪。
   一次資料が必要な作業では、取得できなかった事実を必ず先に伝える。
3. **設定変更は必ずアナウンスしてから。** 設定はユーザーにしか変えられない。
   下のテンプレートで、必要なドメインと手順をまとめて提示する。

## いつ発動するか

- 作業に外部サイトの取得が必要だと分かった時点（**着手前**。試して失敗してからではなく、
  必要だと分かった瞬間にアナウンスするのが望ましい）
- `WebFetch` / `curl` / `pip` / `npm` などがプロキシに拒否された時
- ユーザーが URL を貼ってきて、それが許可リスト外のドメインだった時

## 手順

### 1. まず状況を確認する

```bash
curl -sS "$HTTPS_PROXY/__agentproxy/status"   # 現在のポリシーと許可リスト
cat /root/.ccr/README.md                       # ツール別の対処
```

### 2. 必要なドメインを列挙する

推測で足さない。実際に叩く URL のホスト名を挙げる。サブドメインが複数あるなら
`*.` を使う（`*.example.jp` は全サブドメインにマッチ）。

### 3. アナウンスする（テンプレート）

> **外部サイトの取得がブロックされています。**
>
> 取りに行きたい先：
> - `www.example.go.jp`（〇〇の一次資料 PDF）
>
> 現在の環境のネットワークポリシーが **Trusted**（既定の許可リストのみ）なので、
> このドメインはプロキシが拒否します。私の側では回避できません。
>
> **設定変更の手順**
> claude.ai/code → メッセージ入力欄の上のクラウドアイコン → 対象の環境にホバー →
> 歯車 → **Network access**
>
> **A. Custom（推奨・範囲を絞る）**
> **Allowed domains** に以下を貼り付け：
> ```
> *.go.jp
> *.or.jp
> *.frame.claudeusercontent.com
> ```
> ＋「Also include default list of common package managers」に**チェックを入れたまま**にする
> （外すと npm / PyPI / GitHub raw が落ちます）
>
> **B. Full（何でも通る）**
> ドメイン管理が不要になる。Full でも Anthropic のセキュリティプロキシ・監査ログ・
> 隔離 VM・GitHub 用の別プロキシはそのまま効く。
> トレードオフは、出口制限が無くなるため、私が読み込んだ外部コンテンツに
> プロンプトインジェクションが仕込まれていた場合に送信先を構造的に縛れないこと。
>
> **変更が効くのは新しいセッションからです。** 今のセッションのポリシーは起動時に
> 固定されているので、切り替えたあと新規セッションを開いてください。
>
> どうしますか？ 設定せずに進める場合は、手元にある資料だけで作業して、
> 取得できなかった部分は「未確認」と明示します。

### 4. ユーザーが設定しない／今すぐ変えない場合

作業を止めない。取得できる範囲で進め、**取得できなかった箇所を成果物と報告の両方で
明示する**（「出典未確認」「一次資料未取得」など）。記憶で埋めて出典があるかのように
書かない。

## 必ず伝える注意点

- **`*.frame.claudeusercontent.com` は Custom のとき必須。** これが無いと
  Artifact の読み取り（`action: "read"`）が落ちる。Full なら不要。
- **「Also include default list of common package managers」は原則チェックしたまま。**
  外すと npm / PyPI / crates.io / GitHub raw などが一斉に落ちる。
- **クラウド環境の環境変数に API キーや認証情報を置かない。**
  この環境にはシークレットストアが無く、環境変数はその環境を使う人全員が読める。
  GitHub の認証情報はプロキシ側で注入されるためサンドボックス内には存在しない
  （`GH_TOKEN=proxy-injected` はダミー）。この状態を崩さない。
- 設定変更は**環境単位**。同じ環境を使う他のセッション・他の作業にも効く。
